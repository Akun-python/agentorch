# 克拉克星鸦长时记忆图谱模块实验设计审计

## 审计目的

本审计用于判断 `experiments.long_term_memory_graph` 的实验设计是否：

1. 对硕士论文章节层面的实验要求合规
2. 对“可插拔长时记忆图谱机制”这一方法主张具有说服力
3. 具备继续补强后投稿为独立小论文的基础

本审计关注的是“实验设计与证据链”，不是单纯的代码完成度。

## 总体结论

当前结论分为两层：

- 工程实验模块层面：合格
- 论文章节说服力层面：基本成立，但证据尚未完全闭环

更具体地说：

- 该模块已经具备统一 benchmark、稳定性复现、Neo4j latency、图规模 latency 的实验工具链
- 该模块已经具备强基线组，不再是“只和弱基线比较”的不充分设计
- 该模块已经开始引入多 seed 统计量，不再只给单次结果
- 但该模块仍缺少几类直接决定论文说服力上限的证据：即插即用接入案例、专项机制场景实验、失败模式分析、真实 Neo4j 正式结果

因此，本模块当前适合支撑这样的论文结论：

- “该机制是一个结构清晰、可运行、具有明确实验接口的图谱型长期记忆模块，并在部分关键指标上优于非图谱基线。”

但当前还不适合直接支撑这样的强结论：

- “该机制已经在综合质量上全面优于所有强基线，并具备成熟投稿级证据闭环。”

## 合规性清单

### 1. 研究问题与实验问题是否一致

判定：基本合规

当前实验问题覆盖了以下研究主张：

- 是否优于无长期记忆、纯向量记忆、平面 summary memory、朴素图记忆
- 是否能利用图结构关系提升 relation hit / conflict resolution / stale suppression
- 是否能在 Neo4j 图数据库上完成真实持久化与检索
- 是否能在不同 seed 和不同图规模下保持稳定

仍需补充：

- “可插拔”这一主张目前更多体现在接口设计上，缺少两类不同 agent 封装方式的真实接入案例

### 2. baseline 是否充分

判定：合规

当前 baseline 组已经具备说服力：

- `no_long_term_memory`
- `vector_memory`
- `flat_summary_memory`
- `naive_graph_memory`
- `clarks_nutcracker_graph`

这组 baseline 的优点在于：

- 覆盖“无长期记忆”
- 覆盖“只做语义检索”
- 覆盖“非图结构的平面总结记忆”
- 覆盖“有图但无精细抑制与裁决的朴素图记忆”
- 覆盖“完整机制”

风险边界：

- `flat_summary_memory` 当前是强基线，且在首屏 recall / relevance / usefulness 上可能仍更强
- 这不是坏事，但要求论文叙述必须诚实，不能写成“全面最优”

### 3. 指标设计是否合规

判定：基本合规

当前核心指标：

- `capsule_recall@k`
- `subgraph_relevance`
- `relation_hit_rate`
- `returned_memory_usefulness`
- `stale_node_injection_rate`
- `conflict_resolution_success`

优点：

- 指标与图谱机制目标高度对齐
- 不只看 recall，也看结构关系、陈旧污染和冲突裁决

不足：

- 对首屏摘要质量仍缺少更明确的专项评价
- 对“returned_memory_usefulness”仍主要依赖规则化权重，而非人工标注

### 4. 统计有效性是否足够

判定：从“偏弱”提升到“基本合规”

目前已具备：

- 多 seed 稳定性 benchmark
- 均值、标准差
- bootstrap 95% CI

这意味着结果表达已经不再停留在“只报一个平均值”的阶段。

仍需补充的更强证据：

- 如需冲更强 venue，建议进一步补 paired significance test 或更严格的 bootstrap 差异检验

### 5. 可复现性是否合规

判定：合规

当前已具备：

- 标准 CLI
- 固定输出目录
- 确定性 `embedding_salt`
- 可控 `scale_multiplier`
- pytest 覆盖
- benchmark 产物 JSON / CSV / Markdown 三类输出

风险边界：

- Neo4j 正式实验仍依赖本机认证与运行环境
- 因此真实图数据库实验目前是“工具可复现”，但不等于“结果已复现实测完成”

## 说服力审计

### 已具备说服力的部分

以下结论当前已经有较强支撑：

1. 该模块不是概念草图，而是边界清晰的实验模块
2. 该模块不是只和弱基线比较
3. 该模块的图谱结构优势主要体现在 relation、stale suppression、conflict resolution 上
4. 该模块具备进一步扩展为系统级长期记忆层的工程基础

### 说服力仍然不足的部分

以下主张当前仍不应写得过强：

1. “该机制在整体质量上全面优于所有强基线”
2. “该机制已经证明可无缝插入任意智能体”
3. “该机制在大规模图数据库环境下已得到真实充分验证”

原因分别是：

1. `flat_summary_memory` 仍可能在首屏信息密度上更占优
2. 当前缺少两类真实 agent 封装接入案例
3. Neo4j 图规模 benchmark 工具已完成，但真实环境结果仍需正式跑出

## 当前最关键的缺口

按优先级排序：

### P0

1. 两类不同 agent 封装方式的即插即用接入案例
2. `REVISES / CONFLICTS_WITH / stale suppression` 三类专项场景实验
3. 真实 Neo4j 图规模实验结果
4. 失败模式案例分析
5. 章节可直接使用的 LaTeX 表格产物

### P1

1. 检索链路消融
2. 构边类型消融
3. 参数敏感性分析
4. backfill 后的 recall 实验
5. 首屏摘要质量专项分析

### P2

1. 人工标注相关性评估
2. 更多领域迁移场景
3. Browser 可视化附图

## 验收标准

若目标是“硕士论文章节合格”，建议至少满足：

- 强 baseline 全部保留
- 多 seed 稳定性结果可复现，并报告 95% CI
- 至少 2 类智能体接入案例
- 至少 1 组真实 Neo4j 图规模实验结果
- 至少 3 类专项机制场景实验
- 至少 1 节失败模式分析

若目标是“独立小论文更有说服力”，建议再补：

- 检索链路消融
- 构边类型消融
- 更正式的统计显著性检验
- 更强的人工标注或跨域泛化证据

## 建议的论文口径

当前最安全、最诚实、也最有学术说服力的写法是：

- 本方法在图结构关系命中、冲突裁决和陈旧记忆抑制上表现出稳定优势
- 本方法作为可插拔长期记忆图谱层具有明确工程可部署性
- 本方法在首屏综合质量上仍与强平面基线存在竞争关系，因此后续将继续优化排序、摘要和子图裁决机制

不建议当前直接写：

- “全面超过所有基线”
- “已经验证可插入任意智能体”
- “在大规模图数据库上得到充分系统性证明”
